# AI assistance disclosure

I used **Claude (Anthropic)** as a step-by-step assistant throughout this assessment.

## What the AI did

- **Planning:** broke the assessment into steps and proposed the stack (FastAPI, PostgreSQL, Docker Compose, GitHub Actions, GHCR, Trivy).
- **Code and configuration:** drafted the application code (`app/`), tests (`tests/`), `Dockerfile`, `compose.yaml`, `.env.example`, the CI workflow, and the deploy/rollback scripts. It checked its drafts in its own sandbox (lint, tests, actionlint, shellcheck) before giving them to me.
- **Explanations:** explained some files, commands and design choices so that I understand and can defend them.
- **Troubleshooting guidance:** helped diagnose the Docker Desktop / WSL2 hang (leading to installing Docker Engine in Ubuntu), the GHCR `denied` error in CI, and interpreted the outage-drill output that revealed 500s were not logged or counted; it then drafted the fix released as 1.2.0.
- **Documentation:** drafted the README, runbook, decision memo, security and observability notes, alert rules and the architecture diagram, based on my actual results.

## What I did

- Set up the environment (WSL2 Ubuntu, Docker Engine, GitHub CLI) and fixed my own machine's issues with guidance.
- Created every file, ran every command, and read every output myself. All evidence in `evidence/` comes from my machine and my GitHub account; none of it was generated by AI.
- Verified each step against the expected results before moving on, and investigated failures by reading the logs (CI publish failure, database outage drill).
- Configured GitHub repository and package permissions, made the package public, created the releases (tags 1.0.0, 1.1.0, 1.2.0), and ran the deploy, rollback and failure demonstrations.
- Took the screenshots, reviewed and edited the documentation.

## Limits

- No AI tool had access to my machine, GitHub account or credentials; I ran everything.
- No real customer data, credentials or Apex systems were used.
